# 架构说明

## 系统概览

万州商户通采用前后端分离架构，并由 Nginx 在生产环境统一提供前端静态资源和 API 反向代理。

```text
浏览器
  ├─ merchant.*  商户端
  └─ admin.*     管理端
          │
          ▼
       Nginx
  静态资源 + /api 代理
          │
          ▼
       FastAPI
  认证、业务规则、权限、文件访问
       │       │
       ▼       ▼
   MySQL/SQLite  上传文件卷
```

## 技术分层

### 前端

- Vue 3 和 TypeScript 负责页面与交互。
- Vue Router 负责页面路由、登录守卫和角色访问控制。
- Element Plus 提供基础 UI 组件，ECharts 提供经营图表。
- Axios 统一请求 `/api/v1`，自动携带浏览器会话 Cookie。
- Vite 负责本地开发和生产构建。

关键目录：

```text
frontend/src/
  components/   通用布局、通知中心等组件
  services/     API 请求封装
  stores/       登录会话状态
  views/        业务页面
  portal.ts     商户端/管理端入口识别
  router.ts     路由与权限守卫
```

### 后端

- FastAPI 提供 HTTP API、参数校验和 OpenAPI 文档。
- SQLAlchemy 负责数据模型与查询，Alembic 负责生产数据库迁移。
- Pydantic Schema 区分接口输入、输出和统一响应结构。
- JWT 用于会话令牌，浏览器默认通过 HttpOnly Cookie 传递。
- 业务路由按认证、入驻、商户、经营数据、资源、申请、通知等领域拆分。

关键目录：

```text
backend/
  app/
    routers/    按业务领域拆分的 API
    main.py     应用入口、中间件和健康检查
    models.py   SQLAlchemy 数据模型
    schemas.py  Pydantic 输入输出模型
    deps.py     认证、角色和商户权限依赖
    rules.py    画像与推荐的可解释规则
  alembic/      数据库迁移
  tests/        接口、安全和迁移测试
```

## 双入口与权限模型

### 入口识别

Nginx 根据请求域名将入口角色写入 `X-WST2-Portal` 请求头。前端也会根据子域名识别当前入口：

- `merchant.*` 对应商户端。
- `admin.*` 对应管理端。

后端在登录、注册和已认证请求中再次校验入口与账号角色，前端路由守卫不是唯一的安全边界。

### 权限层级

1. `authenticated_user`：已登录且账号有效。
2. `password_ready_user`：已完成强制改密码。
3. `current_user`：商户账号已通过入驻审核。
4. `operator_only`：仅运营人员可访问。
5. 商户资源权限：商户只能修改自己的档案和经营数据，运营人员可跨商户查看但不代替商户写入业务数据。

## 核心数据

| 模型 | 作用 |
| --- | --- |
| `User` | 登录账号、角色、状态与会话版本 |
| `OperatorInvite` | 运营账号注册邀请码 |
| `MerchantOnboardingApplication` | 商户入驻草稿、提交与审核状态 |
| `LegalEntity` | 商户所属的法定主体 |
| `CredentialDocument` | 入驻资质文件及其安全元数据 |
| `Merchant` | 店铺档案、数字化需求和商品信息 |
| `BusinessData` | 按日归集的经营数据 |
| `ServiceResource` | 可推荐的数字化服务资源 |
| `ServiceApplication` / `ApplicationEvent` | 服务申请与处理时间线 |
| `Notification` | 用户站内通知与已读状态 |
| `AuditLog` | 关键业务操作审计记录 |

## 文件与数据存储

- 开发环境默认使用 SQLite，生产环境使用 MySQL 8.4。
- 商品图片和资质文件存入持久化上传目录，通过 API 在权限检查后返回，不由 Nginx 直接公开。
- 入驻资质文件使用独立密钥加密存储，支持保留历史密钥用于轮换过渡。
- 生产模式不自动建表，数据库结构必须通过 Alembic 迁移。

## 安全基线

- 密码使用 PBKDF2 摘要，不保存明文密码。
- 浏览器会话使用 HttpOnly Cookie，生产环境启用 `Secure` 和严格 SameSite 策略。
- 登录接口同时有 Nginx 限速和应用层尝试次数限制。
- API 响应设置禁止缓存、禁止嵌入和 MIME 嗅探防护头。
- Nginx 设置 CSP、HSTS、Permissions-Policy 和上传大小限制。
- 生产配置会校验密钥长度、密钥隔离、HTTPS CORS 来源和数据库参数。
